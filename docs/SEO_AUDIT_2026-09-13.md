# Auditoria técnica de SEO, indexação e descoberta por IA — 2026-09-13

Domínio canônico: `https://babyavancar.com.br`. Auditoria feita sobre o código real do projeto (Next.js 16.3.5, App Router, deploy Railway, DNS/proxy Cloudflare) mais requisições HTTP reais contra produção. Nenhuma página, telefone, endereço ou perfil social foi inventado — tudo abaixo referencia arquivo/linha ou resposta HTTP real.

Ferramentas às quais este agente **não** tem acesso (limite real da auditoria, não decisão de escopo): painel Cloudflare (regras de firewall/bot management), Google Search Console, Bing Webmaster Tools, Google Rich Results Test, PageSpeed Insights/Lighthouse real, Google Business Profile. Onde isso importa, está marcado como ⚠️ AÇÃO EXTERNA com o passo exato a validar.

---

## Sumário executivo

- **1 problema P0 real e sério**: `https://www.babyavancar.com.br/` responde **404** ("Application not found" do próprio Railway) em vez de redirecionar para o domínio canônico. Causa raiz confirmada: o DNS do `www` está apontado (via Cloudflare) mas **não existe esse domínio cadastrado no serviço Railway** (`railway domain` só lista o subdomínio `.up.railway.app` e o apex `babyavancar.com.br`). Isso é infraestrutura (Cloudflare/Railway), não código — não foi corrigido nesta rodada.
- Fora isso, a base técnica de SEO estava **incomum, para o padrão desses projetos**: robots.txt, sitemap, canonical, JSON-LD, alt text, HTML semântico e conteúdo textual real (sem dependência de JS) já estavam corretos e bem documentados no próprio código.
- 4 fixes P1 seguros foram implementados nesta rodada (detalhe na seção "O que foi corrigido"): imagem Open Graph/Twitter dedicada (não existia nenhuma), `lastModified` falso no sitemap, uso de API de imagem depreciada no Next 16 competindo pelo LCP, e `X-Robots-Tag: noindex` no domínio técnico do Railway para eliminar risco de conteúdo duplicado.
- Nenhum crawler de IA (GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, Claude-SearchBot, Claude-User, PerplexityBot, Perplexity-User) está bloqueado no `robots.txt` — o único bloqueio existente é `/plataforma` e `/api/*`, via wildcard `User-agent: *`. Não foi criada nenhuma regra específica por bot (ver seção 4 — decisão de treinamento de IA não é minha para tomar).

Dado que o objetivo explícito é maximizar descoberta por ChatGPT/Claude/Perplexity, este é o item de maior risco de "bloqueio silencioso" que existe fora do código.

## P3 — otimizações avançadas para IA/AEO/GEO

| # | Item | Observação |
|---|---|---|
| P3-1 | `robots.txt` (`src/app/robots.ts`) | Hoje só existe uma regra `User-agent: *`. Nenhuma regra específica para `GPTBot`, `OAI-SearchBot`, `ChatGPT-User`, `ClaudeBot`, `Claude-SearchBot`, `Claude-User`, `PerplexityBot` ou `Perplexity-User` — todos herdam o wildcard (hoje: **permitidos**). Isso já atende ao objetivo de "máxima capacidade de descoberta" pedido. Uma política explícita por bot (por exemplo, permitir `OAI-SearchBot`/`ChatGPT-User`/`Claude-SearchBot`/`Claude-User`/`PerplexityBot`/`Perplexity-User` e tratar `GPTBot`/`ClaudeBot` — uso para treinamento — separadamente) é uma decisão de produto/negócio, não técnica. **Não implementei nenhuma regra nova** — conforme instrução explícita, essa decisão não é minha para tomar sozinho. |
| P3-2 | `llms.txt` | Não existe hoje. É um recurso experimental, sem padrão estabelecido nem suporte confirmado por Google/Bing/OpenAI/Anthropic/Perplexity como sinal de ranking ou descoberta. Não substitui `robots.txt`, sitemap ou dados estruturados. **Decisão: não criar agora** — o conteúdo do site (2 páginas reais) não justifica mais um artefato para manter sincronizado, e o valor real hoje é incerto. Reavaliar se/quando o site tiver mais conteúdo institucional. |
| P3-3 | `structured-data.tsx` / `site.ts` | `sameAs` do schema `School` só tem o Instagram oficial confirmado. Não há Facebook nem Google Business Profile confirmados no código — por isso não foram adicionados (a instrução foi explícita: só URLs oficiais confirmadas). Se a escola tiver perfil no Facebook e/ou Google Business Profile, adicionar as URLs reais em `SITE` (`src/shared/config/site.ts`) e usá-las em `sameAs` é uma melhoria de baixo risco. |
| P3-4 | Sitemap de imagens | Avaliado e **descartado por ora**: o site é visual mas as imagens relevantes (galeria, atividades) não têm página própria indexável nem são o tipo de conteúdo em que um sitemap de imagens dedicado traria ganho sobre a indexação natural via `next/image` + `alt` já bem descritivo. Reavaliar só se o volume de imagens/páginas crescer muito. |
| P3-5 | `hero.tsx` / seções da Home | Conteúdo textual é sólido e específico (endereços reais, atividades reais, diferenciais reais — nada genérico do tipo "um lugar para crescer" sem contexto). Único ponto observado: a Home não tem, num único bloco, a frase direta "Educação Infantil e Fundamental I" + "duas unidades" + "como agendar visita" resumidos numa única sentença citável — a informação está toda lá, mas espalhada entre Hero/Segmentos/FAQ. Isso já é suficiente para um LLM/answer engine reconstituir a resposta (testado via extração de texto puro do HTML — ver validação). Não é um problema, é uma nota para uma futura seção de "Perguntas frequentes" mais completa. |
